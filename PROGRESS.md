- **C3 (part 1): Agent 4 Evidence Auditor + Agent 3 Road Hazard Sensing + ingestion: done, 303 pytest green**
  - **Auditor** (on `work_order.completed`): hard checks (taken after assignment, GPS within the category radius, not reused by perceptual hash incl. the job's own before-photo, EXIF present) plus a vision check (skipped in rules mode). FAIL→REWORK happens only on hard evidence (GPS > 500 m, reused photo, taken before assignment); the model can't override that either way. Verification queue `GET /control/verification` now includes `audit` (checks, verdict, score, steps).

  - **Ingestion:** `POST /ingest/detections` (array or `{records}`, ≤1000, `X-API-Key: oem-sim-demo-key`, optional `Idempotency-Key`) and `POST /ingest/detections/csv`. Validation (city boundary, not future / older than 30 days, confidence 0–1 defaulting to 0.5, hazard-type mapping, dedupe on source+id). PII fields (vin, rider_name, phone, trip…) are rejected and stripped even from the dead letter. Every failure is stored in `rejected_detections`. Response: `{received, accepted, rejected, duplicates, rejections[{index, source_record_id, reason}]}`.
  - **Sensing** (scheduler every 60 s when new detections arrive; `POST /demo/run/sensing` to run now): PostGIS `ST_ClusterDBSCAN` (12 m, UTM 43N) → persistent `hazard_clusters`. Decisions: CORROBORATE an open complaint within 25 m ("Confirmed by N connected vehicles", priority up at ≥5), REPAIR_FAILURE (repair verified in the last 30 days → crew marked HIGH, new complaint), CREATE (≥3 vehicles and confidence ≥0.8 only, enforced in code), REVIEW (officer queue).
